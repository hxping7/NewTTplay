# 二期：歌词服务器集成进插件（无外挂进程）

> 2026-10-24 交付。一期结论见《逆向报告-千千静听本地歌词服务器.md》。
> 本版已将歌词服务**完整集成进 TTPlayer 进程**：不再有外挂服务器、不再有 127.0.0.1:89 端口。

## 1. 为什么不能"修补"原版

| 方案 | 结论 |
|---|---|
| 给原版 ttp_lrcsh.dll 加导入依赖（进程内起 HTTP 服务） | ❌ SAC 持续拦截（错误 4551）："签名剥离+PE 改动"= 典型篡改特征，云裁定最终判坏事 |
| 外挂 Node 服务器（一期方案） | ✅ 可用，但需单独启动/维护 |
| **全新 DLL 整体替换 ttp_lrcsh.dll，直连音源 API** | ✅ **采用**：全新未签名文件 SAC 放行（实测）；无 HTTP、无端口、无外部进程 |

SAC 实测行为：新文件首次加载触发异步云裁定（可能短暂 4551，稍后重试即放行）；干净的新编译 DLL 最终放行；改动过的签名 DLL 最终拦截。

## 2. TTPlayer 插件 ABI（Ghidra 全函数级实证）

调用链（全部 stdcall、this 作显式首参的 C 风格 vtable）：

```
TTPlayer.exe
 ├─ FindFirstFileW(AddIn\ttp_*.dll) 枚举 → LoadLibrary → GetProcAddress("ttpGetSoundAddIn")
 ├─ ttpGetSoundAddIn(void** ppv)               → 工厂对象(8B) [vtable][ref]
 ├─ factory[3] GetIfaceC(mode 0/1, GUID* out, void** ppv)
 │     → 写 GUID_C 声明"我是歌词插件"；返回歌词对象(12B) [vtable][mode][ref]
 ├─ lyrics[3] GetEngine(void** ppv)            → 引擎对象(0x88B)，QI(GUID_E)
 ├─ engine[3] Initialize(host, initData)
 │     → QI(host, GUID_HOST{6F1F38A8..}) → QI(中级接口, GUID_CB{CA540428..}) = 歌词交付回调
 │     → 启动工作线程（命令队列 + 事件）
 ├─ engine[4] SetSongInfo(wchar* artist, wchar* title) → 投递命令1(搜索)
 │     工作线程: 直连 QQ/酷狗 API → callback[3](cb, count, wchar** artists, wchar** titles) 交付列表
 ├─ engine[5] SelectResult(int index)          → 投递命令2(下载)
 │     工作线程: 取词 → callback[4](cb, len, utf8 data, L"", L"") 交付 LRC
 └─ engine[2] Release → 投递命令3(退出)，等待线程，释放
```

## 3. 本版实现（ttp_lrcsh_new.c，MinGW i686 构建）

- 完整实现上表全部接口与 GUID，stdcall + .def 导出干净名 `ttpGetSoundAddIn`
- 工作线程直连音源：QQ smartbox+lyric、酷狗 mobilecdn+krcs+lyrics（WinINet，走系统代理）
- 结果经 callback[3] 交付（CoTaskMemAlloc 宽串数组，调用后释放）；LRC 经 callback[4] 交付（UTF-8）
- 日志：`AddIn\log\yyyy-MM-dd.txt`
- 已知限制：酷我 API 已加 csrf 反爬未接；QQ smartbox 对部分查询返回空（上游行为，酷狗 12 条结果不受影响）

## 4. 部署与回退

**当前状态**：`AddIn\ttp_lrcsh.dll` = 集成版（69575 字节，2026-10-24 构建）。
**原版备份**：`lyrics-server\lrcsh_original_backup.dll`（42648 字节，未动）。
**回退方法**：TTPlayer 退出后，用备份覆盖 `AddIn\ttp_lrcsh.dll` 即可恢复原版（外挂服务器方案需另行启动 server.js）。

**源码与重建**：
```
cd D:\TTPlayer\AddIn\lyrics-server
D:\mingw32\bin\gcc.exe -m32 -shared -o ttp_lrcsh_new.dll ttp_lrcsh_new.c ttp_lrcsh_new.def -lws2_32 -lwininet -lole32 -O2
```
（.def 文件必须有：mingw 默认会把 stdcall 导出名装饰成 `ttpGetSoundAddIn@4`，而 TTPlayer 按干净名查找）

## 6. v2 修正（2026-10-24 22:45，已部署）

实测反馈「歌词没法下载 + 歌词服务器出现两个本地歌词」，定位到两个缺陷并修复：

1. **交付编码**：宿主 `callback[4]` 第 3 参是 **UTF-16LE 宽字符串**、第 2 参是**宽字符个数**。
   原实现传 UTF-8 字节流 → TTPlayer 把 ASCII 两两打包成汉字（`[id:` → `楛㩤`），落盘 .lrc 全乱码。
   现改为 `MultiByteToWideChar(CP_UTF8)` 转换后交付，缓冲区尾部多留 64 宽字符 0 防越界。
2. **接口数量**：`factory->GetIfaceC(mode)` 原先对 mode 0/1 都返回成功，TTPlayer 每条成功都注册一份插件，
   于是出现两个「本地歌词」。现只放行 `mode==0`，`mode>=1` 返回 `E_FAIL` 结束宿主枚举循环。
3. 附带：`http_get` 改为 PRECONFIG → DIRECT 双路重试，并记录 `GetLastError`（应对偶发 `HTTP -2`）。

验证：`enumiface32.exe` 确认只声明 1 个接口；`mocktt32.exe` 全链路通过且回调内容可读（`[ti:晴天]`）。
详细 ABI、构建/回滚、调试手册见 `开发进度-交接文档.md`。
